# Registro central de fornecedores de API — Ablaw IA

Quando um fornecedor for integrado (WhatsApp, assinatura eletrônica, consulta processual, IA jurídica etc.), registrar aqui:

- Nome do fornecedor
- Link da documentação oficial
- Nome da variável de ambiente do token/chave (ver `.env.example`)
- Observações importantes (limites, particularidades, pontos de falha conhecidos)

| Fornecedor | Documentação | Variável de ambiente | Observações |
|---|---|---|---|
| WaSender (WhatsApp) | https://wasenderapi.com/api-docs (índice em markdown: https://wasenderapi.com/llms.txt) | `WASENDER_API_URL`, `WASENDER_PERSONAL_ACCESS_TOKEN` (secrets das Edge Functions `criar-instancia`/`excluir-instancia`/`wasender-obter-qrcode`, nunca em `.env` do frontend) | Substituiu a GoZAP (migração feita em 19/08/2026 — a conta GoZAP tinha limite de 1 instância no plano Básico, insuficiente). **Não é API oficial da Meta** — camada de automação de terceiros, mesmo risco de bloqueio por uso automatizado que a GoZAP tinha. **Conta compartilhada com o projeto Magnus** (mesmo login WaSender, decisão explícita do usuário — ver `[[project_gozap_single_instance]]` na memória) — mas cada projeto tem sua própria **sessão/instância exclusiva**, nunca reaproveitada entre projetos. **Só suporta QR code** como método de linkagem self-service — o modo Passkey existe mas depende de uma extensão de navegador (Device Link Helper) pra aprovar, não serve pro fluxo do cliente final; **não existe mais** o registro só-por-SMS/ligação que a GoZAP tinha (por isso a opção "SMS/Ligação" foi removida da tela de criar instância). A WaSender exige o telefone **já na criação da sessão** (diferente da GoZAP, que só pedia isso no modo mobile) — `POST /api/whatsapp-sessions` com `name`, `phone_number`, `account_protection`, `log_messages`, devolve `id` (inteiro) e `api_key` própria da sessão. Pra gerar o QR: `POST /api/whatsapp-sessions/{id}/connect` com o **Personal Access Token da conta** (nível de conta, gerencia todas as sessões) — devolve uma **string de dados brutos**, não uma imagem pronta (diferente da GoZAP); a imagem é desenhada no frontend com a lib `qrcode` (`QRCode.toDataURL(...)`). Pra checar status: `GET /api/status`, mas autenticado com a **api_key da própria sessão** (não o Personal Access Token) — são dois tipos de credencial diferentes, não confundir. Pra excluir: `DELETE /api/whatsapp-sessions/{id}` com o Personal Access Token. QR se renova a cada 20s no frontend (mesma cadência do WhatsApp Web), sem endpoint de expiração explícito documentado. **Token exclusivo do Ablow**: gerado com o nome "Ablow IA" em Settings → Personal Access Tokens, revogável independente de outros tokens da mesma conta. |
