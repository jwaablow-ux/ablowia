# Registro central de fornecedores de API — Ablaw IA

Quando um fornecedor for integrado (WhatsApp, assinatura eletrônica, consulta processual, IA jurídica etc.), registrar aqui:

- Nome do fornecedor
- Link da documentação oficial
- Nome da variável de ambiente do token/chave (ver `.env.example`)
- Observações importantes (limites, particularidades, pontos de falha conhecidos)

| Fornecedor | Documentação | Variável de ambiente | Observações |
|---|---|---|---|
| GoZAP (WhatsApp) | https://gozap.dev/docs | `GOZAP_API_URL`, `GOZAP_ADMIN_TOKEN` (secrets das Edge Functions `criar-instancia`/`excluir-instancia`, nunca em `.env` do frontend) | Substituiu a Evolution API (migração feita antes de qualquer instância real existir). Não é API oficial da Meta — camada de automação de terceiros, com risco de bloqueio por uso automatizado; a própria GoZAP recomenda WhatsApp Business. **Decisão: os dois modos de conexão convivem lado a lado**, escolhidos pelo admin por instância no `CriarInstanciaModal` — não existe um modo "padrão" fixo no sistema: <br>• **`companion`** (QR code) — o número já tem WhatsApp instalado num aparelho, que continua sendo o dono da conta pra sempre (desinstalar o WhatsApp do aparelho depois derruba a conexão inteira). Usuário final escaneia o QR sozinho via link público (`gozap-obter-qrcode`).<br>• **`mobile`** (SMS/ligação) — o número é registrado direto na API, sem depender de nenhum celular físico depois. Exige telefone na criação. Usuário final escolhe SMS/ligação e confirma o código sozinho via link público (`gozap-mobile-opcoes-verificacao` → `gozap-mobile-solicitar-codigo` → `gozap-mobile-verificar-codigo`). **Risco real observado em teste**: o WhatsApp pode bloquear (`"reason":"blocked"`) uma tentativa de registro mobile sem aviso prévio e sem relação com o número já ter tido WhatsApp antes (a doc da GoZAP não exige "chip virgem" — SMS/Call funcionam nos dois casos) — é antiabuso genérico da Meta, por isso o modo `companion` existe como alternativa imediata pra qualquer instância. `connection_mode` é imutável após a criação — não há "trocar de modo depois", só recriar a instância. O link público (`/pareamento/:token`, token opaco em `instancias_conexao.link_pareamento_token`) detecta sozinho qual modo mostrar via RPC pública `obter_modo_conexao_publico` (sem expor nenhuma credencial). Todas as Edge Functions públicas usam `SUPABASE_SERVICE_ROLE_KEY` (não há usuário autenticado nesse fluxo), exceto a consulta de modo que é uma RPC direta (`anon`) por não expor nada sensível. Números com 2FA ativado no WhatsApp não são suportados no registro mobile (a própria GoZAP não recomenda) — a Edge Function de verificação devolve erro pedindo para desativar o 2FA. **Ver as conversas dentro do painel Ablaw IA ainda não existe** — não há webhook receiver nem tabela de mensagens; isso é independente do `connection_mode` escolhido e precisa ser construído à parte. **Testado contra a API real** (conta trial, subdomínio temporário): `/instance/create` (companion e mobile), `/instance/connect`, `/instance/status`, `DELETE /instance`, `/instance/mobile/verification-options` e `/instance/mobile/request-code` (este último retornou o bloqueio real do WhatsApp citado acima). `/instance/mobile/verify-code` ainda **não foi testado com sucesso** — nenhuma tentativa chegou a receber um código válido. |
